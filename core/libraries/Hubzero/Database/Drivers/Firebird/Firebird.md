# Firebird Driver

**This is a proof-of-concept driver.** It passed all tests when originally written but is not maintained on a regular testing cadence. It should not be considered production-ready without re-validation against the current test suite.

**This driver requires a patched `pdo_firebird` extension.** The stock PHP `pdo_firebird` has a critical bug where zero-length BLOBs are returned as NULL, silently corrupting empty text values. A one-line C patch to `firebird_statement.c` fixes the fetch path to return empty strings for zero-length BLOBs. Additional `pdo_firebird` issues (no autocommit, MVCC metadata invisibility, RETURNING row exhaustion) are handled by PHP-level workarounds in the driver. See the [Technical Notes](#technical-notes-pdo_firebird-patches) section for details.

**Minimum version: Firebird 3.0+** (for IDENTITY columns and native BOOLEAN).

## Architecture

```
Drivers/Firebird/
  FirebirdDriver.php  extends BaseSqlDriver
  FirebirdSyntax.php  extends BaseSqlSyntax
  FirebirdGrammar.php extends BaseSchemaGrammar
```

`BaseSqlDriver` extends `BasePdoDriver` (PDO connection wrapper), which extends `Driver` (abstract connection lifecycle, query execution, result fetching). All 12 concrete drivers follow this same three-file pattern.

The base class defaults follow MySQL conventions. The Firebird driver overrides expression properties, type maps, identifier quoting (uppercase + double-quote), introspection queries (RDB$ system tables), and has extensive workarounds for `pdo_firebird` transaction and metadata visibility issues.

## Expression Overrides

| Property | Firebird | Base (MySQL) Default |
|----------|----------|---------------------|
| `$nowExpression` | `CURRENT_TIMESTAMP` | `NOW()` |
| `$ifNullFunction` | `COALESCE` | `IFNULL` |
| `$nameQuote` | `"` (double-quote) | `` ` `` |

`$randExpression` and `$lengthFunction` are not overridden — Firebird supports `RAND()` (2.5+) and `CHAR_LENGTH` natively.

## Type System

Firebird has native BOOLEAN (3.0+). Text types use `BLOB SUB_TYPE 1` (text BLOBs), which requires the patched `pdo_firebird` to correctly handle zero-length values. JSON uses `VARCHAR(32765)` since Firebird has no native JSON type and BLOB columns are not queryable with string predicates.

|---------------|--------------|-------|
| `boolean` | `BOOLEAN` | Native true/false (3.0+) |
| `tinyInteger` | `SMALLINT` | No TINYINT |
| `smallInteger` | `SMALLINT` | |
| `mediumInteger` | `INTEGER` | |
| `integer` | `INTEGER` | |
| `bigInteger` | `BIGINT` | |
| `string` | `VARCHAR` | Max 32765 bytes |
| `char` | `CHAR` | |

| `float` | `FLOAT` | |

| `uuid` | `CHAR(36)` | |

No `UNSIGNED` modifier. No `ENUM` type — use VARCHAR with CHECK constraints.

### Auto-Increment via IDENTITY (Firebird 3.0+)

```sql
"ID" INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
```

IDENTITY columns are implicitly NOT NULL. The database manages the internal sequence — no separate `CREATE GENERATOR` or trigger is needed. `RESTART WITH n` sets the current value; the next insert produces n+1.

Legacy generator support is included for backward compatibility with pre-3.0 databases (`findTableGenerator()`, `getGeneratorValue()`, `syncGenerator()`).

## Connection

The constructor builds a PDO DSN:

```
firebird:dbname=host/port:/path/to/database.fdb;charset=UTF8
```

Embedded mode (no host):

```
firebird:dbname=/path/to/database.fdb;charset=UTF8
```

Post-connection configuration:

- **`PDO::ATTR_AUTOCOMMIT = false`** — `pdo_firebird` requires explicit transactions
- **`PDO::ATTR_CASE = CASE_LOWER`** — normalize column names to lowercase for ORM compatibility
- Charset defaults to UTF8

Uses the `pdo_firebird` PHP extension.

## Identifier Quoting

Firebird stores unquoted identifiers as UPPERCASE (SQL standard). The driver uppercases all identifiers and wraps them in double quotes:

```
wrap('users')  →  "USERS"
wrap('email')  →  "EMAIL"
```

Table aliases use space, not AS — though Firebird does support `AS` for table aliases unlike Oracle.

## Query Building (FirebirdSyntax)

### Pagination

Firebird 3.0+ uses SQL:2008 standard OFFSET/FETCH:

```sql
SELECT * FROM "USERS"
OFFSET 10 ROWS FETCH FIRST 20 ROWS ONLY
```

Legacy Firebird 2.x syntax (`ROWS n TO m`) is also supported.

### INSERT / Upsert

Firebird uses `UPDATE OR INSERT` (2.1+):

```sql
UPDATE OR INSERT INTO "TABLE" ("COL1", "COL2")
VALUES (?, ?)
MATCHING ("COL1")
```

The `MATCHING` clause specifies conflict detection columns (defaults to first column if not specified).

### Bulk INSERT

Firebird does not support multi-row `VALUES (...), (...)`. Bulk inserts use `INSERT INTO ... SELECT ... FROM RDB$DATABASE UNION ALL`:

```sql
INSERT INTO "TABLE" ("COL1", "COL2")
SELECT CAST(? AS VARCHAR(100)), CAST(? AS INTEGER)
FROM RDB$DATABASE
UNION ALL
SELECT CAST(? AS VARCHAR(100)), CAST(? AS INTEGER)
FROM RDB$DATABASE
```

`RDB$DATABASE` is Firebird's single-row system table (equivalent to Oracle's DUAL). Column types are determined by querying RDB$ system tables for correct CAST expressions.

### RETURNING Clause

INSERT statements on tables with an `ID` column automatically get `RETURNING "ID"` appended. The returned row is cached internally (see Technical Notes) and used by both `insertid()` and subsequent fetch calls.

### UPDATE with JOIN

Firebird does not support MySQL-style `UPDATE ... JOIN`. The syntax class rewrites it using `RDB$DB_KEY`:

```sql
UPDATE "TABLE" SET "COL" = ?
WHERE RDB$DB_KEY IN (
    SELECT "TABLE".RDB$DB_KEY FROM "TABLE"
    JOIN "OTHER" ON ...
    WHERE ...
)
```

### FROM RDB$DATABASE

Firebird requires a FROM clause for all SELECT statements. Bare SELECTs get `FROM RDB$DATABASE` appended:

```sql
SELECT CURRENT_TIMESTAMP FROM RDB$DATABASE
```

### JSON Support

**Not supported.** Firebird has no native JSON functions. `setJsonPathWhere()`, `setJsonContainsWhere()`, and `setJsonLengthWhere()` all throw `UnsupportedSyntaxException`.

### Date Filtering

```php
// CAST(column AS DATE) = '2024-01-15'
$query->setDateWhere('created', '=', '2024-01-15', 'date');

// EXTRACT(YEAR FROM column) = 2024
$query->setDateWhere('created', '=', 2024, 'year');
```

### Function Translation

| MySQL | Firebird |
|-------|----------|
| `CONCAT(a, b, c)` | `(a \|\| b \|\| c)` |
| `IFNULL(a, b)` | `COALESCE(a, b)` |
| `NOW()` | `CURRENT_TIMESTAMP` |
| `YEAR(col)` | `EXTRACT(YEAR FROM col)` |
| `SUBSTRING(s, p, n)` | `SUBSTRING(s FROM p FOR n)` |
| `CEIL(n)` | `CEILING(n)` |
| `MOD(a, b)` | `MOD(a, b)` (native) |
| `BIT_AND(a, b)` | `BIN_AND(a, b)` |
| `NEXTVAL(gen)` | `NEXT VALUE FOR gen` |
| `CURRVAL(gen)` | `GEN_ID(gen, 0)` |
| `DATE_FORMAT` | Not supported |
| `DATE_ADD/DATE_SUB` | Not supported |

### String Concatenation

Firebird uses the `||` operator. `CONCAT()` is not available as a function.

### TRUNCATE

Firebird has no `TRUNCATE TABLE`. The driver uses:

```sql
DELETE FROM "TABLE"
```

This does not reset generators/identity sequences.

## DDL Generation (FirebirdGrammar)

### CREATE TABLE

Firebird does not support inline regular indexes. `compileCreate()` returns an array: the CREATE TABLE statement plus separate `CREATE INDEX` statements.

```sql
CREATE TABLE "USERS" (
    "ID" INTEGER GENERATED BY DEFAULT AS IDENTITY
        NOT NULL PRIMARY KEY,
    "EMAIL" VARCHAR(255) NOT NULL,
    "NAME" VARCHAR(100)
)
```

No ENGINE, CHARSET, or COLLATION clauses. `GENERATED BY DEFAULT AS IDENTITY` must appear before `NOT NULL PRIMARY KEY`.

### ALTER TABLE

Each operation is a separate statement:

- **ADD COLUMN** — `ALTER TABLE "T" ADD "COL" type`
- **DROP COLUMN** — `ALTER TABLE "T" DROP "COL"`
- **MODIFY COLUMN** — separate statements for TYPE and NOT NULL:
  ```sql
  ALTER TABLE "T" ALTER COLUMN "COL" TYPE new_type;
  ALTER TABLE "T" ALTER COLUMN "COL" NOT NULL;
  ```
- **RENAME COLUMN** — `ALTER TABLE "T" ALTER COLUMN "OLD" TO "NEW"`
- **DROP INDEX** — `DROP INDEX "NAME"`
- **ADD INDEX** — `CREATE [UNIQUE] INDEX "NAME" ON "T" ("COLS")`
- **DROP PRIMARY KEY** — looks up constraint name, then `ALTER TABLE "T" DROP CONSTRAINT "NAME"`
- **ADD PRIMARY KEY** — `ALTER TABLE "T" ADD PRIMARY KEY ("COLS")`
- **DROP FOREIGN KEY** — `ALTER TABLE "T" DROP CONSTRAINT "NAME"`
- **ADD FOREIGN KEY** — `ALTER TABLE "T" ADD FOREIGN KEY ("COLS") REFERENCES ...`

### Table Rename

Firebird has no direct `RENAME TABLE`. The driver implements it by:

1. Get column definitions from RDB$ system tables
2. Create new table with correct schema
3. Copy data from old table
4. Recreate indexes and foreign keys
5. Drop old table

### Column Positioning

Firebird does not support AFTER/FIRST/BEFORE in ALTER TABLE. Column positioning is supported via table recreation — the driver rebuilds the entire table with columns in the desired order.

### Fulltext Indexes

Firebird has no FULLTEXT index type. `addFulltextIndex()` creates a regular index instead.

### Boolean Literals

Firebird's native BOOLEAN type cannot be cast from strings. `formatBooleanLiteral()` returns `'TRUE'`/`'FALSE'` literals (not `'1'`/`'0'`). Bulk inserts inline boolean literals instead of using `CAST(? AS BOOLEAN)`.

## Schema Introspection

Firebird uses RDB$ system tables for introspection:

| Method | Implementation |
|--------|---------------|
| `getTableColumns($table)` | `RDB$RELATION_FIELDS` JOIN `RDB$FIELDS` |
| `getTableKeys($table)` | `RDB$RELATION_CONSTRAINTS` + `RDB$INDEX_SEGMENTS` |
| `getForeignKeys($table)` | `RDB$RELATION_CONSTRAINTS` + `RDB$REF_CONSTRAINTS` |
| `getTableList()` | `RDB$RELATIONS WHERE RDB$SYSTEM_FLAG = 0 AND RDB$VIEW_BLR IS NULL` |
| `tableExists($table)` | `RDB$RELATIONS` count |
| `getPrimaryKey($table)` | `RDB$RELATION_CONSTRAINTS WHERE RDB$CONSTRAINT_TYPE = 'PRIMARY KEY'` |
| `getAutoIncrement($table)` | `RDB$IDENTITY_TYPE` check, fallback to generator `GEN_ID` |
| `getVersion()` | PDO server version attribute |

All RDB$ columns are space-padded CHAR — queries use `TRIM()` to normalize. System table names and values are UPPERCASE in SQL, but PDO returns lowercase property names due to `ATTR_CASE = CASE_LOWER`.

### Numeric Type Codes

Firebird stores column types as numeric codes in `RDB$FIELDS.RDB$FIELD_TYPE`:

| Code | Type |
|------|------|
| 7 | SMALLINT |
| 8 | INTEGER |
| 10 | FLOAT |
| 12 | DATE |
| 13 | TIME |
| 14 | CHAR |
| 16 | BIGINT |
| 23 | BOOLEAN |
| 27 | DOUBLE PRECISION |
| 35 | TIMESTAMP |
| 37 | VARCHAR |
| 261 | BLOB |

BLOB type 261 further distinguishes: sub_type 0 = binary, sub_type 1 = text.

### ENUM (Not Supported)

Firebird has no ENUM type. Use VARCHAR with CHECK constraints.

### Views

- `createOrReplaceView()` — `CREATE OR REPLACE VIEW` (native support in 2.5+)
- `dropView()`, `viewExists()`, `getViews()` — queries `RDB$RELATIONS WHERE RDB$VIEW_BLR IS NOT NULL`

### Sequences (Generators)

Firebird's generators are native sequences:

- `createSequence()` — `CREATE SEQUENCE` with START, INCREMENT
- `dropSequence()` — `DROP SEQUENCE`
- `sequenceExists()` — queries `RDB$GENERATORS`
- `nextSequenceValue()` — `NEXT VALUE FOR name`
- `currentSequenceValue()` — `GEN_ID(name, 0)`

### Feature Detection

| Method | Returns |
|--------|---------|
| `getEngine()` | `'Firebird'` |
| `supportsSequences()` | true |
| `supportsIfNotExists()` | false |
| `supportsDropColumn()` | true |
| `supportsRenameColumn()` | true |

## Transaction Support

Firebird requires all statements to run within transactions (`pdo_firebird` sets `ATTR_AUTOCOMMIT = false`). The driver emulates autocommit behavior:

- **Write operations** (INSERT/UPDATE/DELETE): implicit transaction started in `prepare()`, committed in `execute()`
- **Read operations** (SELECT): implicit transaction started in `prepare()`, committed in `freeResult()` after fetching
- **DDL operations**: detected and auto-committed after execution

Nested transactions via savepoints:

```
transactionStart():
  depth 0 → (implicit transaction already active)
  depth N → SAVEPOINT SP_N

transactionCommit():
  depth 0 → COMMIT
  depth N → RELEASE SAVEPOINT SP_N

transactionRollback():
  depth 0 → ROLLBACK
  depth N → ROLLBACK TO SAVEPOINT SP_N
```

## Workarounds

### BLOB Zero-Length Bug (Patched)

The stock `pdo_firebird` converts zero-length BLOBs to NULL — any empty text value in a BLOB column silently becomes NULL on read. A C-level patch to `firebird_statement.c` in `firebird_fetch_blob()` fixes this by returning `ZVAL_EMPTY_STRING` when the BLOB length is 0, before the code falls through to the allocation path that produced NULL. With the patch applied, both the grammar and driver type maps use `BLOB SUB_TYPE 1` for text columns.

### MVCC Metadata Visibility

Firebird's MVCC means transactions see a snapshot from when they started. After committing DDL (CREATE TABLE, ALTER TABLE), the current connection's transaction may not see the updated metadata in RDB$ system tables. Symptoms include `getTableColumns()` returning empty arrays and `tableExists()` returning false for just-created tables.

The `reconnect()` method creates a fresh connection that sees all committed changes. It includes a 50ms delay to work around `pdo_firebird` server-side metadata cache lag. Metadata queries also call `commitBeforeMetadataQuery()` to commit pending DDL before querying system tables.

As a further fallback, `getTableColumnDefinitions()` queries `RDB$RELATION_FIELDS` and `RDB$FIELDS` separately if the JOIN returns no results, working around cases where the MVCC snapshot sees individual tables but not the join result.

### RETURNING Row Caching

Firebird's INSERT/UPDATE ... RETURNING returns result rows like a SELECT. When `execute()` fetches the row to extract the ID for `insertid()`, the result set is exhausted. The driver caches the RETURNING row in `$cachedReturningRow` so subsequent `fetchObject()`/`fetchAssoc()` calls can still access the data. The cache is cleared after first use.

### DDL Error Recovery

After rapid DROP/CREATE cycles, Firebird's metadata garbage collection may not have completed, causing "index already exists" or "cannot create index RDB$PRIMARY" errors. The driver catches these and retries using `RECREATE TABLE` (an atomic drop-if-exists + create).

### No INSERT IGNORE

Firebird has no INSERT IGNORE syntax. For INSERT...SELECT with ignore mode, `needsRowByRowInsertIgnore()` returns true — the driver breaks it into per-row inserts with error catching.

### SQL Normalization in setQuery()

The `setQuery()` method applies extensive SQL transformations to normalize MySQL-style SQL to Firebird syntax:

- `INTEGER(11)` → `INTEGER` (size removed)
- `TINYINT` → `SMALLINT`
- `DATETIME` → `TIMESTAMP`
- `UNSIGNED` → removed
- `AUTOINCREMENT` → `GENERATED BY DEFAULT AS IDENTITY`
- `AFTER column` / `BEFORE column` → removed (no positioning)
- `IF EXISTS` / `IF NOT EXISTS` → removed
- Bare `SELECT` → adds `FROM RDB$DATABASE`
- `VALUE` (reserved word) → quoted as `"VALUE"`

## Technical Notes: pdo_firebird Patches

The stock PHP `pdo_firebird` extension has several issues. One required a C-level patch to the extension source; the rest are handled by PHP-level workarounds in the driver.

### C-Level Patch Applied

**Zero-Length BLOB Returns NULL**

The stock `pdo_firebird` converts zero-length BLOB values to PHP NULL during fetch. Since Firebird stores TEXT/CLOB as BLOB SUB_TYPE 1, any text column containing an empty string (`''`) returns NULL in PHP. This is a silent data corruption bug — the application cannot distinguish between a stored NULL and a stored empty string.

The fix is a 5-line patch to `firebird_statement.c` in `firebird_fetch_blob()`. When the BLOB length is 0, the patched code returns `ZVAL_EMPTY_STRING` and jumps to cleanup, instead of falling through to the allocation path that produced NULL:

```diff
--- a/ext/pdo_firebird/firebird_statement.c
+++ b/ext/pdo_firebird/firebird_statement.c
@@ -346,6 +346,11 @@
 	/* we've found the blob's length, now fetch! */
+	if (len == 0) {
+		ZVAL_EMPTY_STRING(result);
+		retval = 1;
+		goto fetch_blob_end;
+	}

 	if (len) {
```

The patched `pdo_firebird.so` was built from PHP source at `/tmp/php-src/ext/pdo_firebird` and installed to `/usr/lib/php/20230831/pdo_firebird.so` (original backed up as `.bak.20260212_214105`).

With this fix, text types can safely use `BLOB SUB_TYPE 1` and empty strings round-trip correctly.

### PHP-Level Workarounds (Remaining Issues)

**2. No Autocommit Mode**

`pdo_firebird` requires `ATTR_AUTOCOMMIT = false`. Every SQL statement must execute within an explicit transaction, and DDL does not auto-commit. Without the driver's autocommit emulation, every query would need manual `BEGIN`/`COMMIT` wrapping.

Impact: The driver implements implicit transaction management — starting transactions in `prepare()`, committing writes in `execute()`, and committing reads in `freeResult()`. DDL statements are detected by keyword and auto-committed.

**3. MVCC Metadata Invisibility After DDL**

After committing DDL changes (CREATE TABLE, ALTER TABLE, RENAME), the connection's existing transaction snapshot does not see the updated RDB$ system table metadata. JOINs between system tables are particularly affected — a query joining `RDB$RELATION_FIELDS` and `RDB$FIELDS` may return zero rows even though both tables individually contain the expected data.

Impact: The driver must `reconnect()` after DDL to get a fresh transaction snapshot, with a 50ms delay for server-side cache flushing. Metadata queries commit pending transactions first. `getTableColumnDefinitions()` falls back to separate queries when JOINs fail.

**4. RETURNING Row Exhaustion**

When executing `INSERT ... RETURNING "ID"`, `pdo_firebird` makes the returned row available through the statement's fetch methods. However, fetching once (to extract the ID) exhausts the result set. Any subsequent `loadResult()` or `loadObject()` call returns nothing.

Impact: The driver caches the RETURNING row after the first fetch and serves it to subsequent fetch calls, clearing the cache after use.

**5. Case Sensitivity Mismatch**

`pdo_firebird` returns column names in lowercase by default, but Firebird stores unquoted identifiers as UPPERCASE. Without explicit case normalization, code that expects uppercase column names (matching the database) gets lowercase names from PDO.

Impact: The driver sets `PDO::ATTR_CASE = PDO::CASE_LOWER` at connection time. All ORM code and metadata queries must use lowercase property names.

**6. BOOLEAN CAST Failure**

Firebird 3.0+ has a native BOOLEAN type but `CAST(? AS BOOLEAN)` fails — bound string parameters cannot be cast to BOOLEAN. This breaks bulk inserts that use CAST for type safety.

Impact: The driver uses `TRUE`/`FALSE` literals for boolean values and inlines them directly in bulk INSERT SQL instead of using parameterized CAST expressions.
